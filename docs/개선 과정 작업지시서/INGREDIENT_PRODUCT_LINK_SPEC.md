# 성분 추천 상품 링크 개선 (식약처 데이터 조사, 네이버쇼핑 API 종료, 이름-충돌 성분 제외)

작성일: 2026-10-14 (같은 날 네이버쇼핑 API 종료 확인 → KCA 성분사전 검토 →
네이버쇼핑 일반 검색 링크 + 이름-충돌 성분 제외로 최종 변경, 3~6절 참고)

## 0. 배경 — 문제 상황

성분 추천 카드의 "관련 화장품 검색 →" 링크는 네이버쇼핑 통합검색에
"{성분명} 성분 화장품 인체용 -강아지 ..." 형태의 키워드만 던지는 방식이었다
(`app/services/ingredient_service.py`의 `_build_search_url()`). 실사용
확인 결과, 해당 성분이 들어간 **완제품**이 아니라 그 성분 자체를 원료로
파는 **원료/벌크 판매 상품**이 검색 결과에 섞여 나오는 사례가 보고되었다
(예: "바쿠치올" 검색 시 원료 공급처 상품 노출).

## 1. 식약처(식의약 데이터 포털) 등 공공데이터 활용 가능성 조사

"성분명을 넣으면 그 성분이 든 시중 유통 완제품 목록이 나오는" 공식 정부
데이터 소스가 있는지 조사했다.

**핵심 제약 — 법원 판결로 막힌 "성분→제품" 역조회**: 2017년 서울행정법원
(2016구합81826)이 아모레퍼시픽 등 화장품사 19곳이 식약처를 상대로 낸
소송에서 회사 측 손을 들어줬다. 소비자가 식약처에 "화장품별 원료 목록"
정보공개를 청구했다가 거부당해 제기한 소송으로, 법원은 품목별 전성분
데이터를 **영업상 비밀**로 인정했다 — 18만여 품목의 원료 데이터가 공개되면
경쟁사가 배합 경향을 파악해 유사 제품을 만들 수 있다는 논리였다. 즉 식약처가
보유한 품목별 전성분 DB를 공공데이터로 공개받는 경로는 이 판례로 사실상
막혀 있다.

`data.mfds.go.kr`(식의약 데이터 포털)과 `data.go.kr`에 "화장품 원료성분정보",
"화장품 사용제한 원료정보", "화장품 관련 정보" 등 화장품 카테고리 데이터셋이
있으나, 상세 페이지는 접근이 제한되어 있었고 명칭과 위 판례로 미루어보면
원료 자체의 사전적 정보(배합목적·사용한도·네거티브리스트)이지 "품목명 +
전성분" 형태의 제품별 매핑은 아닌 것으로 판단된다.

유사 서비스("유사 화장품 추천" 프로젝트, velog 개발기)의 실제 사례도 이를
뒷받침한다 — 해당 개발자도 식약처 API는 쓰지 않았고, 성분명 표준화에는
대한화장품협회 성분사전(kcia.or.kr, 크롤링)을, "제품명 + 전성분" 매핑에는
국내 공공데이터가 아니라 해외 사이트 INCIDecoder.com을 크롤링했다.

## 2. 화해(hwahae.co.kr) 검토

사용자 요청으로 화해(국내 대표 뷰티 앱)도 대안으로 검토했다.

- **제공 기능**: 화해 앱 설명("내가 찾는 모든 화장품의 성분 확인")과
  릴리즈노트("좋아하는 제품과 성분이 가장 비슷한 제품을 지금 확인해
  보세요")로 볼 때, 화해의 성분 기능은 **제품 → 그 제품의 성분 확인**과
  **제품 → 성분이 비슷한 다른 제품 추천**(제품 대 제품 비교)이다.
  **성분명 → 그 성분이 든 제품 목록**이라는 역방향 검색은 앱 설명에
  언급되지 않았고, 사이트 자체 검색(`/search`)도 일반 인기 제품 목록만
  보여줄 뿐 성분 기반 필터로 보이지 않았다.
- **API/제휴**: 공개된 Open API나 제휴 프로그램 안내는 확인되지 않았다.
  "광고/제휴문의"(business.hwahae.co.kr)로 개별 문의가 필요한 구조다.
- **결론**: 화해는 "성분→제품" 역방향 검색을 공식 기능으로 제공하지
  않고, 공개 API도 없어 이번 개선의 데이터 소스로 바로 쓸 수 없다. 다만
  "제품 상세 화면에 성분을 투명하게 보여준다"는 UX 방향 자체는
  AI-SkinScope의 성분 추천 카드 설계와 결이 같아 참고할 만하다.

## 3. (폐기됨) 1차 의사결정 — 네이버쇼핑 검색 API 기반 완제품 필터링

최초에는 기존에 쓰던 네이버쇼핑을 **링크 생성이 아니라 서버사이드 API
호출**로 바꿔 결과를 필터링하는 방식(`naver_service.py` 신설, 상품명
원료/벌크 키워드 제외, `category1` 필터, 실패 시 범용 검색 링크로
degrade)을 구현했다(`app/services/naver_service.py`,
`ingredient_service._resolve_search_url()`, `app/core/config.py`의
`naver_client_id`/`naver_client_secret`).

**→ 이후 조사로 네이버쇼핑 검색 오픈API(`openapi.naver.com/v1/search/shop.json`)
자체가 2026-07-31부로 대체 없이 완전히 종료된 것이 확인되어 이 방식은
폐기했다.** NAVER API HUB(네이버클라우드플랫폼 기반 신규 플랫폼,
2026-06-25 오픈)로 블로그/뉴스/카페 검색, 검색어트렌드, 쇼핑인사이트는
이전됐지만 쇼핑/책/전문자료 검색은 이전 대상에서 제외되고 대체 없이
종료됐다. developers.naver.com 신규 앱 등록도 같은 날 마감됐고, 기존
발급 키로도 `shop.json` 호출은 404를 반환한다. 독립된 4개 소스
(waffleboard.io, keyword-lab-delta.vercel.app, keywordcockpit.com,
socialcrawl.dev)로 교차 확인했다. 쇼핑인사이트는 상품 링크가 아니라
카테고리 클릭 트렌드 지수만 제공해 이 용도로 쓸 수 없다. 이 코드
(`naver_service.py`와 관련 설정)는 복구 불가능하므로 삭제했다.

### (검토 후 폐기) 1.5차: KCA 공식 성분사전으로 전체 전환

API 종료를 알게 된 뒤, 한때 "상품을 산다"는 기대 자체를 내려놓고 대한화장품협회(KCA)
공식 성분사전(`kcia.or.kr/cid`, URL: `.../search/ingd_list.php?skind=ALL&sword={urlencode(name_ko)}`)으로
전체 링크를 바꾸는 방향도 검토·구현했다. 커머스가 아니라 성분 정보(배합목적,
INCI 영문명 등)만 제공하는 레퍼런스라 원료/반려동물 오염 위험이 없다는
장점이 있었으나, "이 성분이 든 상품을 추천"한다는 기존 기능의 성격이
바뀌는 트레이드오프가 있어 사용자 피드백으로 폐기했다. "화장품 추천"
(상품 링크)을 유지하는 쪽으로 최종 결정했다.

## 4. 최종 의사결정 — 네이버쇼핑 일반 검색 링크 복귀 + 이름-충돌 성분 제외

API가 없는 상태에서도 쓸 수 있는, URL만으로 접근 가능한 네이버쇼핑 일반
검색 링크(`search.shopping.naver.com`, API 키 불필요)로 되돌아가되, 아래
두 가지를 함께 반영했다.

1. **쿼리 단순화**: 기존에는 "{성분명} 성분 화장품 인체용 -강아지 -반려동물
   -펫 -애견 -고양이" 형태로 수식어와 반려동물 제외 키워드를 모든 성분에
   일괄 적용했다. 그런데 실사용자 테스트(스크린샷, 2026-10-14)에서 이
   조합이 "댕댕이나무열매즙" 검색을 0건으로 만들고(대신 무관한 "인기 상품"이
   노출돼 더 혼란스러움), 제외 키워드를 빼면 반려동물 상품이 그대로
   노출되는 것을 확인했다. "성분/인체용" 같은 수식어는 실제 상품명에 거의
   쓰이지 않아 검색을 불필요하게 좁히기만 한다고 판단해 제거하고, 쿼리를
   `{성분명} 화장품` 수준으로 단순화했다.
2. **이름-충돌 성분은 데이터 단계에서 제외**: "댕댕이나무열매즙"은 그
   이름으로 등록된 화장품 완제품이 네이버쇼핑에 아예 없고, "댕댕이"(강아지
   속어) 문자열 때문에 네이버의 유사상품 매칭이 애견용품 쪽으로 쏠린다.
   쿼리를 아무리 다듬어도 해결되지 않는 구조적 문제라, 검색 쿼리가 아니라
   추천 후보 선정 단계에서 제외하기로 했다. `concern_ingredient_map.json`을
   재생성하는 `scripts/build_ingredient_map.py`를 건드리지 않고도 안정적으로
   제외하기 위해, 데이터가 아닌 서비스 계층(`ingredient_service.py`)에
   `EXCLUDED_INGREDIENT_NAMES` 집합으로 제외 처리했다. 추천에서 빠진 자리는
   그 고민 카테고리의 다음 순위 성분이 채워, 항상 목표 개수(5개)가
   유지된다.

## 5. 구현 요약 (최종)

- `app/services/naver_service.py`: 삭제(네이버쇼핑 검색 오픈API 종료로
  복구 불가).
- `app/services/ingredient_service.py`: `_resolve_search_url()`과
  `naver_service` 의존 제거. `_build_search_url()`을 `{성분명} 화장품`
  단순 쿼리로 되돌리고, 효과 없던 반려동물 제외 키워드 로직은 삭제.
  `EXCLUDED_INGREDIENT_NAMES = {"댕댕이나무열매즙"}` 추가, 추천 선정
  루프를 "앞에서 N개 슬라이스" 방식에서 "제외 대상을 건너뛰며 N개가 찰
  때까지" 방식으로 변경해 제외된 자리를 다음 순위 성분이 채우도록 함.
- `app/core/config.py`: `naver_client_id`/`naver_client_secret` 필드
  제거.
- `app/schemas/agent.py`: `IngredientRecommendation.search_url` 설명을
  "성분명으로 네이버쇼핑에서 관련 화장품을 검색하는 링크"로 단순화.
- `.env.example`/`README.md`: `NAVER_CLIENT_ID`/`NAVER_CLIENT_SECRET`
  안내 제거.

## 6. 알려진 한계

- "성분→제품"의 완전하고 정확한 역조회가 아니라, 텍스트 검색에 기대는
  수준의 개선이다. 네이버쇼핑에 등록되지 않았거나 상품명에 성분명이 직접
  노출되지 않는 제품은 여전히 검색되지 않거나 무관한 결과가 섞일 수 있다.
  이는 한국에 "성분→완제품" 역조회를 제공하는 공식/비공식 데이터 소스
  자체가 없다는(0~2절) 근본 한계에서 비롯되며, 어떤 검색 소스를 쓰든
  완전히 해결되지 않는다.
- 현재는 "댕댕이나무열매즙" 한 건만 이름-충돌로 확인되어 제외 목록에
  있다. 비슷한 증상(엉뚱한 카테고리 상품이 반복 노출)이 다른 성분에서도
  보고되면 `EXCLUDED_INGREDIENT_NAMES`에 추가하는 식으로 대응한다 — 사전
  탐지가 아니라 사후 보고 기반의 대응이라는 한계가 있다.
- 검토했던 대한화장품협회(KCA) 공식 성분사전(`kcia.or.kr/cid`) 연결은
  커머스 오염 위험이 없고 등록 명칭과 매칭률이 높다는 장점이 있어, 추후
  "성분 정보 더보기" 같은 보조 링크로 재검토할 여지가 있다(3절 참고).
