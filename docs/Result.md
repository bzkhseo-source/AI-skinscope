## 3. 이번 최종 점검(코드 QA)에서 발견하고 수정한 사항

기존에 설계·적용된 3건의 수정사항(피부나이 신뢰성, PWA 설치 경험, 점수 재현성)이 실제 코드에 반영되어 있는지 전수 재확인했고, 모두 **정상 반영을 확인**했습니다. 그 과정에서 새로 발견해 이번에 함께 수정한 사항은 다음과 같습니다.

| # | 위치 | 문제 | 조치 |
|---|---|---|---|
| 1 | `app/services/kakao_service.py` | 카카오맵 API가 200 응답이지만 예상과 다른 형식(JSON 파싱 실패 등)을 반환하면 예외가 잡히지 않아, 이미 완료된 피부 분석 결과 전체가 500 오류로 날아갈 수 있었음 | `uv_service.py`와 동일하게 `KeyError`/`ValueError`/`TypeError`/`AttributeError`까지 함께 처리하도록 예외 범위 확장 |
| 2 | `frontend/app.js` (챗봇 응답 렌더링) | AI 챗봇 답변을 `innerHTML`로 직접 삽입해, 모델 응답에 스크립트성 태그가 섞여 나올 경우 실행될 수 있는 잠재적 XSS 지점이었음 | 배지와 답변 텍스트를 `textContent`/`createTextNode`로 분리 삽입하도록 수정 |
| 3 | `frontend/service-worker.js` | 새로 추가된 `/uv-index` 엔드포인트가 캐시 제외 목록에 없어, 오프라인 폴백 시 오래된 자외선 지수가 캐시에서 반환될 수 있었음 | `/analyze`, `/history`, `/share/`와 함께 `/uv-index`도 캐싱 제외 목록에 추가 |
| 4 | `docs/SCORE_CONSISTENCY_TEST_LOG.md` | 최종 결정값이 `GEMINI_TEMPERATURE=0.15`라고 기록되어 있었으나, 실제 코드는 이후 재조정을 거쳐 `0.2`로 되어 있어 문서와 코드가 어긋나 있었음 | 실제 코드 값(0.2, 절충안)에 맞춰 로그 문서의 결정 사항을 수정 |
| 5 | `app/services/chat_service.py` (피부지식 챗봇) | 메인 Gemini 모델(`gemini-3.6-flash`)의 무료 티어 일일 할당량(20회)이 소진되면 `429 RESOURCE_EXHAUSTED`가 발생하는데, 대체 모델 없이 바로 고정 안내 문구("지금은 답변이 어려워요...")로 대체되어 사실상 챗봇이 먹통이 됐었음(실사용 중 발견) | `vision_service.py`의 분석 파이프라인과 동일하게 기본 모델 실패 시 대체 모델(`gemini-3.5-flash-lite`)로 자동 전환하도록 수정. 두 모델은 쿼터가 완전히 분리되어 있어 실제로 정상 응답 복구를 확인 |

1, 2, 5번은 실제 오류(또는 기능 마비)로 이어질 수 있는 코드 결함이었고, 3, 4번은 사소하지만 방치하면 혼란을 줄 수 있는 항목이라 함께 정리했습니다.

### 정책 변경: 나이 미입력 시 피부나이 비표시

기존에는 나이를 입력하지 않아도 `compute_skin_age()`가 feature_scores와 가장 가까운 연령대를 인구통계적으로 독립 추정해 피부나이를 보여줬습니다. 그런데 이 추정치는 실제 나이와 비교할 기준점이 없어 "왜 이 나이가 나왔는지" 설명하기 어렵고, 사용자에게 근거 없는 숫자로 오해를 줄 수 있다는 지적에 따라 정책을 변경했습니다. 나이를 입력하지 않으면 피부나이를 아예 계산하지 않고, 결과 화면에 "실제 나이가 입력되지 않아 분석할 수 없습니다" 안내를 대신 표시합니다(`app/services/vision_service.py`의 `compute_skin_age()`, `frontend/app.js`의 결과 렌더링 반영).

## 4. 알려진 한계 (수정하지 않고 남겨둔 항목)

검토 과정에서 발견했지만 이번에는 고치지 않고 기록만 남기는 항목입니다. 코드 정확성 문제는 아니고, 설계·운영상의 트레이드오프이거나 검증에 실기기·실 API 키가 필요한 항목입니다.

- **비동기 라우터 내 동기 블로킹 호출**: `/analyze`, `/uv-index` 라우터는 `async def`로 선언되어 있지만 내부적으로 동기 방식의 Gemini/외부 API 호출을 그대로 사용해, 요청 처리 중에는 다른 요청이 지연될 수 있습니다. 소규모 실사용자 테스트에서는 문제가 되지 않았으나, 트래픽이 늘어나면 스레드 오프로딩(`def`로 변경하거나 `run_in_threadpool` 사용)을 검토할 필요가 있습니다.
- **CORS 전체 허용(`allow_origins=["*"]`)**: 쿠키 기반 인증을 쓰지 않아 당장 위험도는 낮지만, 제출용 코드로서는 허용 출처를 좁히는 편이 안전합니다.
- **얼굴 자동 감지 기능**: 구현은 완료되었으나 실제 카메라 환경에서 직접 검증되지 않았습니다. 또한 감지기가 특정 프레임에서 일시적으로 예외를 던지면 자동 촬영 전체가 영구 중단되던 버그를 발견해 수정했습니다(연속 8회 실패 시에만 중단하도록 변경).
- **자외선 지수 기능**: 로컬 `.env`의 실제 키로 OpenWeatherMap API를 직접 호출해 정상 동작(HTTP 200, 정상 값 반환)을 확인했습니다. 다만 `.env`는 Git에 커밋되지 않으므로, 배포 환경(Render)에도 `UV_API_KEY`가 별도로 등록되어 있는지는 배포 플랫폼에서 직접 확인이 필요합니다.

## 6. 결론

핵심 파이프라인(멀티모달 분석·RAG ×2·AI Agent·Long-term Memory)과 실사용자 피드백 기반 확장 기능(피부나이, 부위별 분석, 성분·퍼스널컬러 추천, 자외선 연동, 지식 챗봇, 점수 재현성 개선)이 모두 코드 수준에서 정상 동작함을 확인했고, 서비스는 실제로 배포되어 접속 가능한 상태입니다. 이번 점검과 실사용 과정에서 실제 결함 3건(카카오맵 예외 처리, 챗봇 XSS, 챗봇 쿼터 소진 시 무응답)을 발견해 수정했고, 자외선 지수 기능은 실 API 키로 최종 검증까지 완료했습니다. 남은 항목은 얼굴 자동 감지 기능의 실기기 검증뿐입니다.
