## 3. 이번 최종 점검(코드 QA)에서 발견하고 수정한 사항

기존에 설계·적용된 3건의 수정사항(피부나이 신뢰성, PWA 설치 경험, 점수 재현성)이 실제 코드에 반영되어 있는지 전수 재확인했고, 모두 **정상 반영을 확인**했습니다. 그 과정에서 새로 발견해 이번에 함께 수정한 사항은 다음과 같습니다.

| # | 위치 | 문제 | 조치 |
| --- | --- | --- | --- |
| 1 | `app/services/kakao_service.py` | 카카오맵 API가 200 응답이지만 예상과 다른 형식(JSON 파싱 실패 등)을 반환하면 예외가 잡히지 않아, 이미 완료된 피부 분석 결과 전체가 500 오류로 날아갈 수 있었음 | `uv_service.py`와 동일하게 `KeyError`/`ValueError`/`TypeError`/`AttributeError`까지 함께 처리하도록 예외 범위 확장 |
| 2 | `frontend/app.js` (챗봇 응답 렌더링) | AI 챗봇 답변을 `innerHTML`로 직접 삽입해, 모델 응답에 스크립트성 태그가 섞여 나올 경우 실행될 수 있는 잠재적 XSS 지점이었음 | 배지와 답변 텍스트를 `textContent`/`createTextNode`로 분리 삽입하도록 수정 |
| 3 | `frontend/service-worker.js` | 새로 추가된 `/uv-index` 엔드포인트가 캐시 제외 목록에 없어, 오프라인 폴백 시 오래된 자외선 지수가 캐시에서 반환될 수 있었음 | `/analyze`, `/history`, `/share/`와 함께 `/uv-index`도 캐싱 제외 목록에 추가 |
| 4 | `docs/SCORE_CONSISTENCY_TEST_LOG.md` | 최종 결정값이 `GEMINI_TEMPERATURE=0.15`라고 기록되어 있었으나, 실제 코드는 이후 재조정을 거쳐 `0.2`로 되어 있어 문서와 코드가 어긋나 있었음 | 실제 코드 값(0.2, 절충안)에 맞춰 로그 문서의 결정 사항을 수정 |

1, 2번은 실제 오류로 이어질 수 있는 코드 결함이었고, 3, 4번은 사소하지만 방치하면 혼란을 줄 수 있는 항목이라 함께 정리했습니다.

## 4. 알려진 한계 (수정하지 않고 남겨둔 항목)

검토 과정에서 발견했지만 이번에는 고치지 않고 기록만 남기는 항목입니다. 코드 정확성 문제는 아니고, 설계·운영상의 트레이드오프이거나 검증에 실기기·실 API 키가 필요한 항목입니다.

- **비동기 라우터 내 동기 블로킹 호출**: `/analyze`, `/uv-index` 라우터는 `async def`로 선언되어 있지만 내부적으로 동기 방식의 Gemini/외부 API 호출을 그대로 사용해, 요청 처리 중에는 다른 요청이 지연될 수 있습니다. 소규모 실사용자 테스트에서는 문제가 되지 않았으나, 트래픽이 늘어나면 스레드 오프로딩(`def`로 변경하거나 `run_in_threadpool` 사용)을 검토할 필요가 있습니다.
- **CORS 전체 허용(`allow_origins=["*"]`)**: 쿠키 기반 인증을 쓰지 않아 당장 위험도는 낮지만, 제출용 코드로서는 허용 출처를 좁히는 편이 안전합니다.
- **얼굴 자동 감지 기능**: 구현은 완료되었으나 실제 카메라 환경에서 직접 검증되지 않았습니다.
- **자외선 지수 기능**: 실제 API 키로 최종 응답 검증이 아직 이루어지지 않았습니다.
