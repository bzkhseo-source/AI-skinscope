# AI-SkinScope 기능 요구 명세서

작성일: 2026-08-31

## 1. 개요

- 프로젝트명: AI-SkinScope
- 목적: 스마트폰 카메라로 촬영한 얼굴 사진을 AI가 분석해 피부 상태 점수와 참고용 관리 가이드를 제공하고, 시간에 따른 변화를 추적하는 개인 피부 코칭 서비스
- 대상 사용자: 피부 트러블 상태를 스스로 판단하기 어려운 일반 대중

## 2. 기능 요구사항 (FR)

| ID | 기능명 | 설명 | 우선순위 |
| --- | --- | --- | --- |
| FR-01 | 사진 촬영/업로드 | 폰 카메라로 피부 부위 즉시 촬영 또는 갤러리 업로드 | Must |
| FR-02 | 촬영 전 동의 절차 | 개인정보(민감정보) 수집 동의 체크박스, 저장/삭제 정책 안내 | Must |
| FR-03 | AI 이미지 분석 | Gemini Vision으로 모공·탄력·수분·주름·색소침착·붉은기 특징 추출 | Must |
| FR-04 | 피부 건강 점수 산출 | 분석 결과 기반 0~100점 수치화(한국인 피부상태 측정 데이터 기준 백분위 anchor) | Must |
| FR-05 | 유사 증상 카테고리 안내 | "진단 아님" 고지 포함, 5종 패턴(건선/아토피/여드름/지루피부염/주사) 유사도 안내 | Must |
| FR-06 | 전문의 상담 권장 트리거 | 심각도 임계값 초과 시 병원 방문 권장 + 카카오맵 병원 검색 도구 호출 | Must |
| FR-07 | 관리 루틴 코칭 메시지 | 분석 결과 기반 생활 습관/관리 팁 생성(AI 생성 콘텐츠 명시) | Must |
| FR-08 | 이력 저장 (Long-term Memory) | 사용자별 촬영 기록·점수 DB 저장 | Must |
| FR-09 | 변화 추적 리포트 | 이전 기록 대비 점수 변화, 이력 조회 | Must |
| FR-10 | 사용자 피드백 수집 | 분석 결과 만족도/의견 입력 폼 | Must |
| FR-11 | 결과 히스토리 조회 | 과거 촬영 이력 리스트/상세 조회 | Should |
| FR-12 | 데이터 삭제 요청 | 사용자가 본인 데이터 삭제 가능 | Should |
| FR-13 | 나이·성별 입력 + 동년배 비교 + 피부나이 | 선택 입력한 나이·성별로 동년배 평균과 비교, 피부나이 산출(신뢰도 낮으면 안내로 대체) | Should |
| FR-14 | 부위별(이마/코/양볼/턱) 세분화 분석 | 얼굴을 5개 구역으로 나눠 모공·유분·트러블 상태 제공 | Should |
| FR-15 | 결과 공유 | Web Share API/클립보드 복사로 점수·요약 공유(원본 사진 미포함) | Should |
| FR-16 | AI 소견 구조화 | 핵심 소견 → 동년배 비교 → 관리 제안 순으로 구조화된 소견 제공 | Should |
| FR-17 | "진단 아님" 문구 노출 최소화 | 최초 1회만 강조 고지, 근거 투명성(접이식) 섹션 제공 | Could |
| FR-18 | 촬영 가이드(오버레이 + 자동 감지) | 타원 가이드라인, 밝기/거리 실시간 안내, 얼굴 자동 감지 시 자동 촬영 | Should |
| FR-19 | 자외선 지수 연동 | 현재 위치 기준 UV 지수·행동 요령 안내 | Could |
| FR-20 | 퍼스널컬러 추천 | 분석 사진 기반 피부 톤에 어울리는 컬러 팔레트 제안 | Could |
| FR-21 | 피부지식 챗봇 | 분석 결과에 대한 자유 질의응답(RAG 기반, 의료 진단성 질문은 전문의 상담으로 안내) | Should |
| FR-22 | 이력분석 리포트 | 저장된 전체 이력의 6개 항목+종합점수를 항목별 그래프로 시각화하고, 추세에 따른 AI 생성 관리 피드백 제공 | Should |

## 3. 비기능 요구사항 (NFR)

| ID | 항목 | 요구사항 |
| --- | --- | --- |
| NFR-01 | 응답 속도 | 사진 업로드 → 분석 결과까지 10초 이내 |
| NFR-02 | 개인정보 보호 | 사진·건강정보 암호화 저장, 접근 권한 최소화 |
| NFR-03 | 가용성 | 배포 URL 상시 접근 가능 |
| NFR-04 | 사용성 | 모바일 브라우저에서 카메라 접근 3탭 이내 |
| NFR-05 | 투명성 | 모든 결과 화면에 "AI 생성/진단 아님" 고지 상시 노출(단, 반복 노출은 최소화) |
| NFR-06 | 확장성 | Long-term Memory용 DB는 사용자 수 증가 대비 정규화된 스키마로 설계 |
| NFR-07 | 일관성 | 동일 사진 반복 분석 시 점수 편차를 낮게 유지(Gemini 호출 temperature 고정) |

## 4. AI 활용 명세

| 기능 | AI 활용 방식 | 상세 설명 |
| --- | --- | --- |
| 피부 특징 추출(FR-03, 04) | 멀티모달 AI(Gemini Vision) | 얼굴 사진 → 6개 항목 + 부위별 상태를 구조화된 JSON으로 직접 추출 |
| 채점 근거 보강(FR-04) | RAG(질환 유사사례) | 질환 이미지 데이터 임베딩 인덱스에서 top-5 유사사례 검색 → 판단 근거로 프롬프트에 주입 |
| 채점 근거 보강(FR-04) | RAG(인구 실측 프로필) | 한국인 피부상태 측정 데이터 임베딩 인덱스에서 top-5 검색 → 백분위 anchor 근거로 주입 |
| 전문의 상담 판단·병원 검색(FR-06) | AI Agent | 점수·패턴 판단 결과를 바탕으로 "병원 검색 도구"를 자율적으로 호출할지 결정 |
| 동년배 비교·피부나이(FR-13) | 결정론적 계산 + Long-term Memory | Gemini를 재호출하지 않고, 저장된 인구 실측 통계와 사용자 feature_scores를 비교해 계산 |
| 변화 추적(FR-09) | Long-term Memory | 사용자별 촬영 이력을 DB에 누적, 이전 기록과 비교 |
| 성분 추천(FR-07 확장) | 텍스트 코퍼스 분석 + 특이도 스코어링 | 성분-효능 텍스트 전수 분석 후 고민별 특이도 랭킹을 사전 계산, 실시간에는 조회만 수행 |
| 피부지식 챗봇(FR-21) | RAG + LLM | 질문을 임베딩 → 지식베이스(FAQ+성분 매핑)에서 유사 문서 검색 → 근거 기반 답변 생성, 의료 진단성 질문은 전문의 상담으로 안내 |
| 자외선 지수(FR-19) | 자동화 워크플로우 | 위치 좌표 → 외부 API(OpenWeatherMap) 호출 → 지수·행동 요령 가공해 응답 |
| 이력분석 리포트(FR-22) | 결정론적 계산(그래프) + LLM(피드백) | 그래프 데이터는 저장된 결과만으로 선형회귀 계산(Gemini 재호출 없음), 그 추세를 근거로 텍스트 전용 Gemini 호출을 별도로 1회 실행해 관리 피드백 생성 — 자동 로드가 아닌 사용자가 버튼을 눌렀을 때만 호출 |

## 5. 시스템 아키텍처

```text
[Frontend: PWA (Vanilla JS)]
   카메라 촬영/업로드 (+ 나이·성별 선택 입력)
        │ HTTPS
        ▼
[Backend: FastAPI]
   Vision Service ──▶ Gemini Vision (+RAG ×2 근거 주입) ──▶ feature_scores/overall_score
        │
        ▼
   Agent Service ──▶ 전문의 상담 판단 ──▶ 카카오맵 병원 검색 (도구 호출)
        │                     └▶ 성분 추천(특이도 스코어링) / 피부나이·동년배 비교(결정론적 계산)
        ▼
   Memory Service ──▶ DB(SQLite) 저장 ──▶ 이력 조회 시 재사용
        │
        ├──▶ Chat Service (RAG) ──▶ 분석 결과 기반 자유 질의응답
        └──▶ UV Service ──▶ OpenWeatherMap 자외선 지수 조회
        ▼
   Vercel (배포) ──▶ https://ai-skinscope.vercel.app
```
