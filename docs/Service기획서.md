## 2. 문제 정의 및 핵심 가설

피부 트러블이 생겼을 때 "병원에 갈 정도인지" 스스로 판단하기 어렵습니다. 인터넷 검색은 정보가 파편적이고 불안을 키우며, 병원은 매번 방문하기엔 시간·비용 부담이 있고, 기존 앱들은 진단 없이 정보만 나열합니다.

핵심 가설: 사진 한 장으로 즉시 참고용 스크리닝 결과와 관리 가이드를 받고, 시간 흐름에 따른 변화를 확인할 수 있다면 병원 방문 시점을 더 합리적으로 판단할 수 있다.

### 페르소나

| 페르소나 | 니즈 |

| 김민지 (26세, 직장인) | 지금 상태가 그냥 뾰루지인지 심각한 건지 빨리 알고 싶다 |
| 박준호 (32세, 직장인) | 내 피부가 나아지고 있는지 나빠지고 있는지 기록하고 싶다 |
| 이서연 (20세, 대학생) | 제품을 바꾼 뒤 실제로 좋아졌는지 객관적으로 확인하고 싶다 |

## 3. AI 활용 방식 및 기술적 의사결정

| 기술 요소 | 역할 | 상세 |
| --- | --- | --- |
| 멀티모달 AI (Gemini Vision) | 이미지 분석 | 얼굴 사진 → 모공/탄력/수분/주름/색소침착/붉은기 6개 항목 + 부위별(이마/코/양볼/턱) 상태를 구조화된 JSON으로 추출 |
| RAG ×2 (분석용) | 근거 기반 채점 | ① 질환 유사사례 임베딩(`reference_embeddings.json`) top-5 검색, ② 인구 실측 프로필(`reference_measurements.json`) top-5 검색 — 둘 다 `gemini-embedding-2`(768차원) 코사인 유사도 기반. Gemini에 "강한 참고 근거"로 주입해 채점 일관성을 높임 |
| RAG ×1 (챗봇용) | 지식 기반 질의응답 | 성분-고민 매핑 + 스킨케어 FAQ를 임베딩한 지식베이스에서 질문과 유사한 문서를 검색해 답변 생성 |
| AI Agent | 의사결정 및 도구 호출 | 분석 결과 기반 ① 건강 점수 산출 ② 유사 증상 패턴 안내(진단 아님) ③ 심각도 임계값 초과 시 카카오맵 병원 검색 "도구" 자율 호출 ④ 성분 추천 |
| Long-term Memory | 개인화·추적 | 사용자별 촬영 이력 DB 저장 → 동년배 비교, 피부나이 산출, "지난 기록 대비" 추적에 활용 |

핵심 기술 요소(멀티모달 AI, RAG, Long-term Memory, AI Agent)를 모두 포함해 설계했습니다.

### 왜 언급빈도 대신 특이도(specificity) 기반 성분 추천인가

성분 추천 초기 설계는 임베딩 유사도 검색이었으나, 실제 텍스트 코퍼스 분석 결과 상위 언급 성분이 모든 고민 카테고리에서 겹치는 "차별화 부족" 문제가 발견되어, 특정 고민에만 상대적으로 자주 등장하는 성분에 가중치를 주는 특이도/lift 스코어링으로 전환했습니다(상세: `docs/개선 과정 작업지시서/INGREDIENT_SPECIFICITY_SPEC.md`). 사전 계산된 JSON 조회만으로 충분히 차별화된 추천이 가능해, 실시간 임베딩 검색 인프라 없이도 구현 목표를 달성했습니다.

### 왜 DB 실측 데이터로 점수를 보정하지 않는가 (방향 3: 신뢰도·추적성 보강)

분석에 쓰이는 인구 실측 프로필 RAG(위 표)는 원래 Gemini 채점의 "참고 근거 주입"용으로만 쓰였으나, 이 유사 사례들로 점수 자체를 보정(k-NN 기반 결정론적 override)할 수 있는지 leave-one-out 백테스트로 검증했습니다. 참조 풀을 300명 → 965명(AI Hub 데이터셋에서 사진·라벨이 모두 있는 전원)으로 3.2배 확장해도, 임베딩 유사도 기반 k-NN 추정값의 평균 오차는 0~100점 척도에서 약 12~21점 수준으로 줄지 않았습니다. 즉 오차의 원인은 참조 데이터 양이 아니라 얼굴 사진 임베딩이라는 표현 방식 자체의 해상도 한계로 판단했습니다. 따라서 Gemini가 산출한 `feature_scores`는 그대로 유지하고, 사진과 가장 닮은 실측 사례들의 평균과 사용자 점수를 비교한 투명성 코멘트(`similar_case_note`)만 결과에 추가로 노출하기로 결정했습니다 — 점수를 바로잡는 근거가 아니라, 판단 과정을 투명하게 보여주기 위한 참고 정보입니다(상세: `docs/개선 과정 작업지시서/SIMILAR_CASE_TRANSPARENCY_SPEC.md`).

### 시계열 변화 분석과 AI 관리 피드백 (이력분석)

이력 화면의 "이력분석" 버튼은 저장된 전체 촬영 기록의 6개 항목(모공·탄력·수분·주름·색소침착·붉은기)과 종합점수를 각각 선형회귀로 추세화해 그래프로 보여주고, 그 추세를 근거로 Gemini가 생성한 관리 피드백을 함께 제공합니다. 그래프 데이터 자체는 Gemini를 다시 호출하지 않고 저장된 결과만으로 결정론적으로 계산하며(비용 없음), AI 피드백만 별도의 텍스트 전용 Gemini 호출로 생성해 자동 로드가 아닌 사용자가 버튼을 눌렀을 때만 비용이 발생하도록 설계했습니다.

## 4. AI Hub 개방 데이터 활용

| 데이터셋 | 접근 가능 여부 | 활용 방식 |
| --- | --- | --- |
| 피부 질환 진단 의료 이미지 | ❌ 사용 불가(오프라인 안심존, 학생 개인 접근 불가) | 미사용 |
| 안면부 피부질환 이미지 합성 데이터 | ✅ | 5종 질환(건선/아토피/여드름/지루피부염/주사) 판단 기준의 few-shot 근거 |
| 한국인 피부상태 측정 데이터 | ✅ | 6개 항목 백분위 anchor, 연령대×성별 그룹 프로필, 부위별 실측 anchor의 기준 데이터, 유사사례 투명성 코멘트용 참조 풀(965명) |

원본 이미지는 재배포하지 않으며, 실사용자 테스트는 AI Hub 데이터가 아닌 동의 받은 실제 테스터 본인 사진만 사용했습니다.

## 6. 시스템 아키텍처

```text
[Frontend: PWA (Vanilla JS)]
   카메라 촬영/업로드 (+ 나이·성별 선택 입력)
        │ HTTPS
        ▼
[Backend: FastAPI]
   Vision Service ──▶ Gemini Vision (+RAG ×2 근거 주입) ──▶ feature_scores/overall_score
        │                                                      (+ similar_measurements, RAG 결과 재사용)
        ▼
   Agent Service ──▶ 전문의 상담 판단 ──▶ 카카오맵 병원 검색 (도구 호출)
        │                     ├▶ 성분 추천(특이도 스코어링) / 피부나이·동년배 비교(결정론적 계산)
        │                     └▶ 유사 실측사례 투명성 코멘트 생성(점수는 미보정, 방향 3)
        ▼
   Memory Service ──▶ DB(SQLite) 저장 ──▶ 이력 조회 시 재사용
        │
        ├──▶ Chat Service (RAG ×1) ──▶ 분석 결과 기반 자유 질의응답
        └──▶ UV Service ──▶ OpenWeatherMap 자외선 지수 조회
```

## 8. 비기능 요구사항 및 AI 윤리

`docs/기능요구명세서.md` 3장(NFR-01~07)을 그대로 유지합니다. 핵심 원칙:

- 모든 결과 화면에 "AI 참고용 스크리닝, 의료 진단 아님" 상시 고지 (반복 노출은 최소화하되 최초 고지는 유지)
- 건강 점수·소견·챗봇 답변은 AI 생성 콘텐츠임을 표기
- 심각도가 높으면 병원 방문을 권장하는 방향으로 Agent 로직 설계, AI 결과만으로 방문을 미루지 않도록 안내
- 민감정보(사진·건강정보)는 명시적 동의 하에 수집, 사용자가 언제든 삭제 요청 가능

## 9. 배포 현황 및 남은 검증 항목

- **외부 공개 배포**: **완료.** Vercel(프론트)과 Render(백엔드 API)에 배포되어 **<https://ai-skinscope.vercel.app>**에서 정상 접속을 확인했습니다. 외부에서 접근 가능한 배포 상태입니다.
- **얼굴 자동 감지(로드맵 C)**: 구현은 완료했으나 실제 카메라가 있는 브라우저 환경에서 직접 검증하지 못했습니다. 저사양 기기 버벅임 여부, CDN 모델 로딩 안정성 확인이 필요합니다.
- **자외선 지수(로드맵 J)**: 코드는 완료했으나, 실제 OpenWeatherMap API 키로 최종 응답 검증이 필요합니다.
- **유사 실측사례 투명성 코멘트(방향 3, FR-23)**: 구현·단위 테스트 완료. Gemini의 `feature_scores`는 변경 없이 유지됩니다.
